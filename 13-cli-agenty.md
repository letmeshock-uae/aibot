# Топик 13. CLI и терминальные ИИ-агенты

Многие дизайнеры никогда не открывали терминал (командную строку) и воспринимают его как «территорию разработчиков». Но именно в терминале сегодня работают самые мощные ИИ-агенты для создания продуктов — и для дизайнера, который серьёзно занимается вайбкодингом, освоить базовые команды стоит того: терминальные агенты видят весь проект целиком (а не один файл, вставленный в чат), сами запускают и проверяют результат, и умеют работать с git — системой версий, в которой хранится история изменений кода (подробнее про git — в топике «Вайбкодинг»).

**CLI** (command line interface) — это интерфейс, где вместо кнопок вы печатаете текстовые команды и получаете текстовый ответ. Установка происходит один раз через специальную команду, после чего инструмент запускается прямо из папки с проектом.

## Как устроен агент изнутри: loop и harness

Два слова, которые часто всплывают в разговорах про агентов и которые стоит понимать хотя бы в общих чертах, не углубляясь в инженерию. **Loop (агентный цикл)** — это повторяющийся цикл «подумать → сделать действие → посмотреть на результат → подумать снова», который агент прогоняет много раз подряд, пока задача не решена: именно поэтому Claude Code может сам написать код, запустить тесты, увидеть ошибку и тут же её исправить — без единого нового промпта от пользователя между этими шагами. **Harness («упряжь», обвязка агента)** — это программа-каркас вокруг самой модели, которая даёт ей возможность вообще что-то делать: подключает инструменты (чтение и правку файлов, запуск команд, доступ к MCP), решает, когда останавливаться и спрашивать подтверждение (топик выше про «режимы одобрения»), и удерживает историю сессии. Сам Claude Code (как и Codex CLI, Gemini CLI) — это и есть harness: модель внутри одна и та же, что и в обычном чате, но именно harness превращает её из собеседника в агента, способного довести проект до результата.

## Как физически открыть терминал

Это буквально первый шаг, на котором теряется человек, который «никогда не открывал терминал», и его стоит расписать по кнопкам, а не считать самоочевидным:

- **На Mac:** нажать `Cmd + Пробел` (открывается Spotlight-поиск), напечатать «Terminal», нажать Enter. Либо через Finder: Приложения → Служебные программы → Terminal. Откроется чёрное или белое окно с мигающим курсором — это оно и есть.
- **На Windows:** нажать клавишу `Win`, напечатать «PowerShell» или «Терминал», нажать Enter. Откроется синее окно с мигающим курсором.

В обоих случаях команды набираются построчно и запускаются клавишей Enter — в отличие от привычных программ, здесь нет кнопок и меню, только текст.

## Что нужно поставить один раз перед любым из инструментов ниже: Node.js

Codex CLI и Gemini CLI устанавливаются командой `npm install...` — а `npm` появляется в системе только вместе с **Node.js**, средой выполнения JavaScript вне браузера. Если при попытке установки терминал отвечает «command not found: npm» — значит, этого шага не хватает. Установка одна и та же на Mac и Windows: зайти на [nodejs.org](https://nodejs.org/), скачать установщик версии LTS (рекомендованная, самая стабильная), запустить его и пройти мастер установки, ничего не меняя по умолчанию. После установки терминал нужно закрыть и открыть заново, а затем проверить, что всё встало, командой `node -v` — она должна напечатать номер версии, а не ошибку.

## Windows и Claude Code: важная оговорка

Codex CLI и Gemini CLI после установки Node.js работают на Windows напрямую, без дополнительных шагов. С Claude Code сложнее: он рассчитан на Unix-подобное окружение, поэтому на Windows его нужно ставить и запускать не в обычном PowerShell, а внутри **WSL (Windows Subsystem for Linux)** — встроенной в Windows прослойки, которая даёт полноценный Linux-терминал внутри системы. WSL включается один раз через `wsl --install` в PowerShell от имени администратора и требует перезагрузки — этот шаг стоит закладывать заранее, а не ожидать, что команда установки Claude Code сработает в обычном Windows-терминале с первого раза.

## Claude Code (Anthropic)

Установка (macOS/Linux, а на Windows — внутри WSL, см. выше):
```
curl -fsSL https://claude.ai/install.sh | bash
```
Запуск в папке проекта:
```
cd my-project
claude
```
После этого можно сразу писать задачу на обычном языке:
```
claude "напиши тесты для модуля авторизации, запусти их и почини всё, что не проходит"
```
Claude Code умеет работать в «трубе» (**pipe**, обозначается символом `|`) с другими командами. Труба — это способ передать вывод одной команды на вход другой напрямую, без промежуточного файла: например, команда `tail -200 app.log` сама по себе просто печатает последние 200 строк лог-файла в терминал, а `|` перенаправляет этот текст сразу в Claude Code вместо того, чтобы копировать его руками:
```
tail -200 app.log | claude -p "скажи, если видишь в логах что-то подозрительное"
```

## Codex CLI (OpenAI)

Установка (одинаково на Mac, Linux и Windows — если Node.js уже стоит, см. выше):
```
npm install -g @openai/codex
```
Запуск и постановка задачи:
```
codex "добавь переключатель тёмной темы на главный экран"
```
Codex CLI также принимает изображения — можно передать скриншот макета:
```
codex --image "./screens/homepage.png"
```

## Gemini CLI (Google)

Установка (одинаково на Mac, Linux и Windows):
```
npm install -g @google/gemini-cli
```
Запуск интерактивной сессии в текущей папке:
```
gemini
```
Или разовый вопрос без диалога:
```
gemini -p "объясни структуру этого проекта простыми словами"
```

## Как этим пользоваться дизайнеру

Дизайнеру не обязательно становиться разработчиком, чтобы этим пользоваться: базовый сценарий — скачать/открыть готовый проект (например, сгенерированный в v0 или Figma Make), открыть терминал в этой папке и естественным языком попросить агента что-то поправить: перекрасить кнопку, поправить отступы, добавить анимацию. Разница с обычным веб-чатом в том, что агент реально видит и правит все файлы проекта сразу, а не один фрагмент кода, вставленный вручную.

Отдельно стоит объяснить «режимы одобрения»: по умолчанию агент спрашивает подтверждение перед каждым действием (создать файл, удалить строку, выполнить команду), но можно включить более автономный режим, где агент действует без остановок на каждом шаге — это быстрее, но требует больше доверия к задаче и обязательной проверки результата в конце.

## Настройка агента под свою команду: rules, skills, CLAUDE.md/AGENTS.md

По умолчанию агент ничего не знает про конвенции конкретного проекта — какой стек используется, как называть файлы, какой линтер запускать перед коммитом. Это можно не объяснять заново в каждой сессии: почти все терминальные агенты умеют один раз прочитать специальный файл-инструкцию прямо из папки проекта и дальше держать его в виду на протяжении всей работы. У Claude Code это файл `CLAUDE.md` в корне проекта, у большинства других агентов принято похожее имя `AGENTS.md` — по сути один и тот же принцип под разными названиями (топик «AI-first дизайн-системы» подробно разбирает такой файл на примере готовой дизайн-системы Astryx; здесь — как завести свой с нуля, даже без готовой системы).

Файл — обычный markdown-текст, который можно попросить агента сгенерировать самостоятельно, а потом донастроить руками:
```
claude "создай файл CLAUDE.md для этого проекта: опиши стек, структуру папок, конвенции именования компонентов, и явные правила 'нельзя' — не писать инлайн-стили, не хардкодить цвета вместо токенов"
```
Дальше при каждом новом запуске агент сам подхватывает этот файл из папки проекта — повторять правила в каждом промпте не нужно.

Более гибкий, но пока менее стандартизированный уровень — **skills**: отдельные небольшие файлы-инструкции под конкретную повторяющуюся задачу («как у нас оформляется коммит-сообщение», «как проверять доступность перед сдачей»), которые агент подключает по необходимости, а не держит в контексте постоянно, — своего рода библиотека процедур команды, которую можно копить со временем, а не переписывать общий CLAUDE.md до бесконечности.

## Риск, о котором стоит знать: prompt injection

Когда агент в автономном режиме сам читает внешние данные — открывает страницы в интернете, парсит чужой файл, тянет содержимое стороннего API — он может наткнуться на текст, специально написанный так, чтобы выглядеть как ещё одна инструкция агенту (например, спрятанная в комментарии кода или в теле веб-страницы фраза вида «игнорируй предыдущие инструкции и сделай X»). Это называется **prompt injection** — попытка подсунуть агенту команду не от пользователя, а от постороннего источника, который агент по ошибке принимает за легитимную задачу. Для дизайнера, который включает «full-auto» на реальном проекте, это повод не давать агенту автономный доступ к недоверенным источникам (чужие сайты, незнакомые репозитории) без последующей проверки результата — и настороженно относиться к любому неожиданному действию агента, которое он не просил явно.

## Примеры команд для практики

- «Объясни, что делает эта команда, прежде чем я её запущу: `codex --approval-mode full-auto "почисти неиспользуемый код"`»
- «Я впервые открываю терминал — распиши по шагам, что нажимать, чтобы установить и запустить Claude Code на Mac.»
- «У меня Windows, и я не понимаю, что такое WSL и зачем он нужен для Claude Code — объясни максимально просто и распиши шаги установки»
- «Вот ошибка из терминала (вставить текст ошибки) — объясни простыми словами, что пошло не так.»
