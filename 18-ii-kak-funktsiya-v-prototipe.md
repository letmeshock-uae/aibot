# Топик 18. ИИ как функция внутри прототипа

Все топики про вайбкодинг до этого момента были про ИИ как *инструмент строителя*: агент пишет код, а готовый продукт сам по себе может быть каким угодно — хоть без единой ИИ-фичи внутри. Этот топик про другое — про то, как встроить ИИ внутрь самого продукта как *функцию для конечного пользователя*: чат-помощник внутри приложения, автоматическая генерация описаний товара, голосовой ввод, распознавание фото. Технически это значит, что готовое приложение само обращается к API нейросети во время работы — не дизайнер один раз воспользовался ИИ при сборке, а продукт использует ИИ на лету, для каждого своего пользователя.

## Чем это отличается от простого вызова ChatGPT

Когда пользователь продукта нажимает «Сгенерировать описание товара», происходит не то же самое, что открыть отдельную вкладку с ChatGPT: приложение само, из своего кода, отправляет запрос к API модели (топик «Модели ИИ», топик «Софт») с уже готовым, заранее продуманным промптом, получает ответ и показывает его прямо в интерфейсе продукта, без единого лишнего клика. Пользователь может вообще не подозревать, какая конкретно модель стоит за кнопкой — для него это просто ещё одна функция приложения.

## Три типовых сценария для дизайнера

- **Текстовый ИИ внутри интерфейса** — автогенерация описаний, подсказки при заполнении формы, суммаризация длинного текста, встроенный чат-помощник. Технически агенту нужно передать: какую модель вызывать, какой system prompt зашить в код (топик «Фундамент» — это тот же system prompt, только теперь пишет его не пользователь чат-бота, а сам продукт), и что показывать, пока ответ ещё не пришёл.
- **Изображения на лету** — генерация аватара, вариаций дизайна, обложки — прямо в потоке работы пользователя, без похода во внешний генератор изображений.
- **Голос и распознавание** — голосовой ввод вместо печати, надиктовка заметки, распознавание объекта на загруженном фото — задействует те же принципы TTS/STT и мультимодальности, что и в топиках «Генерация голоса и аудио» и «Фундамент», только встроенные внутрь продукта, а не как отдельная функция чат-бота.

## Что важно продумать дизайнеру, даже не касаясь кода

- **Состояние ожидания.** Ответ модели приходит не мгновенно — нужен явный индикатор «генерирую», а не замёрзший интерфейс, который выглядит как поломка.
- **Что показать, если модель ошиблась или не ответила.** Это прямое продолжение принципа graceful failure из топика «Принципы дизайна ИИ-продуктов» — нужен понятный fallback, а не пустой экран.
- **Стоимость каждого вызова — не абстракция.** В отличие от личного чата с лимитом сообщений (топик «Тарифы и лимиты»), здесь каждое нажатие кнопки пользователем продукта стоит владельцу продукта реальных денег через API — это меняет решения о дизайне: например, стоит ли давать генерировать неограниченное число раз подряд, или лимитировать в самом интерфейсе.
- **Доверие и разметка результата.** Если результат сгенерирован ИИ и показан как есть — стоит явно обозначить это в интерфейсе, а не выдавать за обычный контент продукта (см. топик «Этика, приватность и ограничения», принцип маркировки ИИ-контента).

## Как поставить задачу агенту

```
claude "добавь в форму создания товара кнопку 'Сгенерировать описание с ИИ': по нажатию отправляй название и категорию товара в API [модель], показывай спиннер во время ожидания, вставляй результат в поле описания с возможностью отредактировать вручную, и покажи понятное сообщение об ошибке, если запрос не прошёл"
```

## Примеры команд для практики

- «Придумай 3 места в приложении [описать продукт], где ИИ-функция реально решает задачу пользователя, а не добавлена просто чтобы был ИИ»
- «Спроектируй состояние загрузки и состояние ошибки для кнопки "Сгенерировать с ИИ" — что видит пользователь в обоих случаях»
- «Мы планируем разрешить безлимитную генерацию картинок в приложении — посчитай примерно, во что это выльется по стоимости API при 1000 активных пользователей в месяц, и предложи разумный лимит»
- «Проверь этот экран с ИИ-функцией на маркировку: понятно ли пользователю, что результат сгенерирован, а не написан человеком»
