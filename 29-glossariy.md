# Топик 29. Глоссарий терминов

Компактный список, доступный из любого места бота одной кнопкой. Сгруппирован по тем же категориям, что и карта топиков в `README.md` — если не помнишь, к какой теме относится термин, ищи в соответствующем разделе.

## Промптинг и модели

- **Промпт** — текстовая инструкция для ИИ
- **JTBD (jobs to be done)** — способ описывать пользователя через задачу, которую он «нанимает» продукт решить, а не через демографию; см. топик «Поиск и ресерч контента»
- **Токен (в LLM)** — единица измерения текста для модели; не путать с «дизайн-токеном» ниже: это два разных термина с одинаковым названием
- **Контекстное окно** — объём текста, который модель «помнит» за раз
- **Температура** — параметр случайности/творчества ответа
- **Система-промпт (system prompt)** — скрытая базовая инструкция, задающая поведение модели до реплики пользователя
- **Few-shot / zero-shot** — промпт с примерами результата / без примеров
- **Chain-of-thought** — пошаговое рассуждение модели вместо мгновенного ответа
- **Структурированный вывод** — ответ в заданном формате (таблица, список, JSON)
- **Мультимодальность** — способность модели принимать текст, изображения, файлы и т. д.
- **Мета-промптинг** — приём, когда одну модель просят написать или улучшить промпт для другого инструмента
- **Оркестрация** — использование нескольких ИИ-моделей вместе в одном рабочем процессе, каждая под свою сильную сторону
- **Галлюцинация** — уверенный, но неверный ответ модели
- **LLM (large language model)** — большая языковая модель, основа текстовых чат-ботов
- **Fine-tuning (дообучение)** — процесс донастройки уже готовой модели на своих данных, чтобы она устойчиво воспроизводила нужный стиль или знала специфику проекта; LoRA — один из способов сделать это без переобучения всей модели
- **RAG (retrieval-augmented generation)** — режим, когда модель сначала находит релевантные данные/документы, а потом отвечает на их основе

## Изображения, видео и аудио

- **Диффузионная модель** — тип модели, генерирующей изображение из шума
- **Негативный промпт (negative prompt)** — список того, чего не должно быть на изображении, используется в диффузионных моделях
- **CFG Scale** — параметр диффузионной модели, насколько строго она следует промпту
- **Sampler / Steps** — алгоритм и число шагов «проявления» изображения из шума
- **Seed** — число, фиксирующее случайность генерации для повторяемого результата
- **Инпейнт / аутпейнт** — перерисовка части изображения / дорисовка пространства за его границами
- **Контрольный сигнал (control signal) / ControlNet** — механизм, жёстко фиксирующий часть композиции (позу, контур, глубину) при генерации изображения
- **Референс по стилю/персонажу (style/character reference)** — приложенное изображение, чей стиль или черты модель переносит на новый результат (`--sref`, `--cref` в Midjourney)
- **Вес промпта (prompt weight)** — числовой множитель, усиливающий влияние части промпта на результат
- **Апскейл** — увеличение разрешения изображения ИИ-методом
- **Схемы освещения (butterfly/Rembrandt/split/rim lighting)** — операторский словарь постановки света для фотореалистичных промптов; см. топик «Генерация изображений»
- **Image-to-video / text-to-video** — оживление готового изображения / генерация видео с нуля из текста
- **Управление камерой (camera control)** — словарь движений камеры в промпте для видео (dolly, pan, orbit и др.)
- **LoRA** — маленькая дообученная надстройка над базовой моделью для своего стиля
- **Чекпоинт** — сохранённая версия локальной модели
- **TTS (text-to-speech) / STT (speech-to-text)** — синтез голоса из текста / распознавание речи и превращение её в текст
- **Voice cloning (клонирование голоса)** — воспроизведение конкретного реального голоса по образцу записи; требует явного согласия человека, чей голос клонируется, см. топик «Этика, приватность и ограничения»
- **Голосовой режим (voice mode)** — функция в приложениях чат-ботов для разговора с моделью вслух в реальном времени, без отдельных шагов расшифровки и озвучки
- **Говорящий аватар / lip-sync** — видео, где сгенерированный или загруженный аватар произносит текст с синхронизацией движения губ под звук (HeyGen, Synthesia); требует согласия человека, если аватар создан по видео реального человека

## CLI, агенты и вайбкодинг

- **Агент** — ИИ-инструмент, который сам выполняет цепочку действий, а не просто отвечает текстом
- **CLI (command line interface)** — текстовый интерфейс командной строки/терминала
- **Agent loop (агентный цикл)** — повторяющийся цикл «подумать → сделать действие → посмотреть на результат» внутри агента; см. топик «CLI и терминальные ИИ-агенты»
- **Harness (обвязка агента)** — программа-каркас вокруг модели, которая даёт ей инструменты, память и правила остановки, превращая её из собеседника в агента
- **Режим одобрения (approval mode)** — настройка, определяющая, спрашивает ли агент подтверждение перед каждым действием
- **Prompt injection** — попытка подсунуть ИИ-агенту скрытую команду через внешние данные (веб-страницу, файл), которую агент по ошибке принимает за инструкцию пользователя
- **MCP (Model Context Protocol)** — открытый клиент-серверный стандарт подключения ИИ-агентов к внешним инструментам и источникам данных (Figma, Google Drive, Slack, Jira и т. п.); подробнее в топике «Софт»
- **Second Brain (второй мозг)** — постоянная, накапливающая контекст личная ИИ-система (заметки + модель с доступом к ним), в противовес разовому кастомному ассистенту; см. топик «Софт»
- **Claude Skill** — файл-инструкция, который подключается один раз и дальше сам активируется по ключевым словам, обучая Claude конкретному формату или процессу; см. топик «Продакшн-процессы»
- **Graph-фреймворк (agent graph)** — способ описать многошаговый ИИ-сценарий как схему из шагов и переходов между ними, а не один большой промпт; см. топик «ИИ как функция внутри прототипа»
- **Git / commit / branch / pull request** — система версий кода и её базовые понятия: сохранённый снимок изменений, параллельная версия для экспериментов, предложение слить изменения
- **Merge conflict** — ситуация, когда git не может сам объединить изменения от двух человек в одном файле и просит выбрать вариант вручную; нормальная часть совместной работы, не поломка
- **i18n (интернационализация)** — подготовка продукта к нескольким языкам интерфейса: тексты вынесены в отдельные файлы перевода, а не вшиты в код напрямую
- **Деплой** — публикация проекта в интернете по реальному адресу
- **Rollback** — откат проекта к предыдущему рабочему состоянию после неудачной правки; см. топик «Чтение и отладка кода агента»
- **Эндпоинт (API endpoint)** — конкретный адрес, на который одна часть приложения отправляет запрос другой (например, `/api/orders`), чтобы получить или изменить данные
- **CRUD** — четыре базовые операции с данными: Create/Read/Update/Delete: создать, прочитать, изменить, удалить
- **SQL** — язык запросов к базе данных, на котором формулируются операции CRUD (например, `SELECT * FROM orders` (прочитать все заказы))
- **Внешний ключ (foreign key)** — поле в одной таблице базы данных, которое указывает на строку в другой таблице, связывая их между собой
- **DevTools** — встроенные инструменты разработчика в браузере (открываются клавишей `F12`), показывают ошибки и сетевые запросы страницы

## Дизайн-системы

- **Дизайн-токен (design token)** — именованное значение стиля в дизайн-системе (например, цвет бренда или отступ), синхронизированное между Figma и кодом; см. топик «AI-first дизайн-системы»
- **CLAUDE.md / AGENTS.md** — файл-инструкция в корне проекта, который агент читает один раз и держит в виду всю сессию: стек, конвенции, что можно и нельзя; см. топики «CLI и терминальные ИИ-агенты» и «AI-first дизайн-системы»
- **Storybook / Storybook MCP** — инструмент, где каждый компонент дизайн-системы хранится как изолированная документированная карточка; MCP-версия делает эти данные доступными агенту напрямую
- **Figma Code Connect** — функциональность Figma, которая явно связывает конкретный компонент в макете с конкретным компонентом в реальном коде

## UX ИИ-продуктов

- **Quiet AI / Visible AI** — ИИ-функция, работающая незаметно фоном, в противовес явно выделенной, сознательно вызываемой пользователем функции; см. топик «UX-паттерны для ИИ-функций»
- **Agentic UX** — проектирование интерфейса для ИИ-агента, который сам совершает действия в продукте, а не только отвечает текстом: уровни автономности, guardrails, approval flow; см. топик «UX-паттерны для ИИ-функций»
- **Human-in-the-loop** — принцип, при котором финальное решение по определённому классу действий всегда остаётся за человеком, без опции полной автономии ИИ
- **Маркировка ИИ-контента (AI disclosure)** — раскрытие того, что материал создан или существенно доработан ИИ; в части юрисдикций и площадок это юридическое требование, а не вопрос личного выбора
- **Ментальная модель (mental model)** — то, как пользователь представляет себе работу системы, часто ошибочно перенесённое из опыта с другим софтом
- **Калиброванное доверие (calibrated trust)** — соответствие уровня доверия пользователя реальной надёжности системы, не выше и не ниже
- **Graceful failure** — спроектированное «мягкое» поведение системы при ошибке, не разрушающее доверие пользователя
- **Эвристическая оценка (heuristic evaluation)** — проверка интерфейса по формальному чек-листу принципов юзабилити
